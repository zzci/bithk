# FIX-070 - Trashed entries invisible in trash view (owner + subfolder scope gap)

- Status: Completed
- Plan: -
- Created: 2026-07-10

## Problem (user-reported)

Files moved to trash in a project's drive never appear in the trash view,
which looks like a hard delete. The rows are intact in the database
(`drive_entries.status = 'trash'`) — this is a display/scope defect, not
data loss. Three gaps:

1. The sidebar trash view queries only the personal space root:
   `useDriveEntries(null, "trash", { ownerType: "user", ownerId })`
   (`-drive-entry-list.tsx`). Project / team-directory trash has no UI
   entry point at all.
2. `trashDriveEntry` keeps the original `parentEntryId`, but
   `listDriveEntries` always filters on an exact parent — a file trashed
   alone from inside a subfolder is invisible even in the personal trash.
3. `DELETE /drive/entries/trash` hard-codes `personalOwner(user.id)`, so a
   project's trash can never be emptied.

## Fix

Backend (`apps/api/src/modules/drive`):

- New service `listTrashedDriveEntries(db, owner)`: all trash-root entries
  for an owner — `status = 'trash'` AND parent is missing or not itself
  trashed (self left-join) — so a trashed folder shows once, not its whole
  subtree. Newest first.
- New route `GET /drive/entries/trash?ownerType&ownerId` via
  `resolveListOwner` (same permission gate as listing).
- `DELETE /drive/entries/trash` accepts `ownerType`/`ownerId` via
  `resolveCreateOwner` (write-level); default stays the personal space.

Web (`apps/web`):

- `useTrashedEntries(owner)` hook + owner-aware `useEmptyTrash` against the
  new/changed endpoints (`shared/lib/api/drive.ts`).
- Sidebar trash view switches to the owner-wide query (fixes subfolder
  invisibility) — `-drive-entry-list.tsx`.
- FileBrowser (project / team surfaces; personal keeps the sidebar entry)
  gains a trash view rendered as a pseudo-folder breadcrumb, with restore,
  delete-forever, and empty-trash actions, manage-gated for writes —
  `-file-browser.tsx`, `extraActions` toolbar slot in the shared surface.
- New i18n keys `browser.action.emptyTrash`,
  `browser.dialog.emptyTrashTitle/Desc` (en + zh).
