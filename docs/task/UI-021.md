# UI-021: Immutable lowercase project code, moved to settings sidebar bottom

- Status: Done
- Plan: [PLAN-034](../plan/PLAN-034.md)
- Owner: Project coordination
- Created: 2026-05-28

## Problem

The project number/code is an editable field in the General settings form and is
auto-generated in uppercase (`P-${shortId.toUpperCase()}`). The update service and
update Zod schema both accept `code`, so it can be mutated after creation. The user
wants the code lowercase, immutable after creation, removed from General, and pinned
to the bottom of the project settings dialog left sidebar with a copy control.

The requested placement is lowercase, immutable, copyable, and outside the
General settings form.

## Acceptance Criteria

- [x] Project code is stored and displayed in lowercase wherever this task touches it.
- [x] Auto-generated codes are lowercase; any supplied initial code is normalized to
      lowercase at creation.
- [x] Project code cannot be changed after creation: the update API ignores/rejects
      `code`, and the General form no longer submits it.
- [x] The editable code field is removed from `ProjectSettingsGeneral`.
- [x] The code appears at the bottom of the settings dialog left sidebar with a copy
      control that has an accessible label and uses existing toast/error conventions.
- [x] Existing create flow stays coherent (auto-code path yields a lowercase value).
- [x] Tests cover lowercase generation/normalization, update immutability, and the
      General form no longer rendering/submitting code.
- [x] Narrow tests run; `bun run check` attempted. Failures from unrelated active
      campaigns are reported, not fixed.

## Notes

- No schema/migration change: the `code` column already exists and stays.
- Out of scope: role/capability redesign (sibling), tag abstraction, access-issue
  parity, migration generation.
