## Summary

Raise the default per-file upload ceiling from 10 MiB to **200 MB**, and make
the env knob MB-denominated for easier editing.

The env var `MAX_UPLOAD_BYTES` (a raw byte count) is replaced by `MAX_UPLOAD_MB`
(default `200`). `loadConfig` derives the internal `MAX_UPLOAD_BYTES`
(`MAX_UPLOAD_MB × 1024²`) in one place, so every downstream consumer (~40 call
sites and test fixtures) keeps reading `config.MAX_UPLOAD_BYTES` unchanged — the
resolved `Config` shape is identical. The Bun server's `maxRequestBodySize` is
derived as `MAX_UPLOAD_BYTES + 64 KiB` (`apps/api/src/index.ts`), so the server
body limit scales automatically — no separate body-limit change is needed.

## Acceptance Criteria

- Env knob is `MAX_UPLOAD_MB` (MB), default `200`; old `MAX_UPLOAD_BYTES` env var
  removed. `loadConfig` derives `config.MAX_UPLOAD_BYTES = MAX_UPLOAD_MB * 1024 * 1024`.
- `Config` exposes the same `MAX_UPLOAD_BYTES: number` field as before
  (`Omit<ParsedEnv, "MAX_UPLOAD_MB"> & { MAX_UPLOAD_BYTES }`), so no consumer or

- Consistency: `.env.example`, generated `docs/reference/env-reference.md`, and
  `docs/modules/file.md` reflect `MAX_UPLOAD_MB`. Web `useUploadLimits` FALLBACK
  stays in bytes (200 MiB) — the API still reports `maxFileSize` in bytes.
- `bun run check` passes.

## Notes — S3 / presigned upload (answered during this task)

- S3 presigned **upload** is **not** supported. The file module has a pluggable
  `FileStorageDriver` registry but ships only the `local` driver; the interface
  exposes `presignDownload` (signed GET) but **no** `presignUpload`. All uploads
  stream through the API (`driver.put`) and are capped by `MAX_UPLOAD_*`. Adding
  S3 presigned upload would need an S3 driver plus a new presign-PUT capability
  and request/confirm endpoints — a separate feature.
