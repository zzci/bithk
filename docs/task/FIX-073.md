# FIX-073 - OIDC outbound requests have no timeout and block the request path

- Status: In Progress (investigation; awaiting proposal approval)
- Plan: [PLAN-111](../plan/PLAN-111.md)
- Owner: audit-remediation/session-2026-09-01
- Created: 2026-09-01

## Goal

`apps/api/src/modules/account/auth/oidc.ts` never passes an `AbortSignal` to
oauth4webapi (token exchange, userinfo, refresh, revocation), and
`oauthSessionAuthProvider` awaits the refresh-token grant inline whenever the
access token has expired. A hung IdP therefore pins every request of that
session until the runtime gives up on the socket. The hand-rolled revocation
fallback in the same file already carries a 5 s timeout, so the gap is an
omission, not a design choice.

## Scope

- One module constant (10 s, matching OIDC discovery) applied through the
  shared options bag to every oauth4webapi request.
- The auth provider starts the refresh without awaiting it (mutex kept); the
  request proceeds on the still-valid session. The app never uses the access
  token per request, so a late refresh changes nothing user-visible.
- No new env var.

## Verification

- RED: `oidc.test.ts` captures the `fetch` init and asserts an `AbortSignal`
  is present on the refresh and userinfo requests.
- RED: `auth.service.test.ts` stubs a never-resolving token endpoint and
  asserts the provider still resolves the user promptly.
- `bun run check` EXIT 0.
