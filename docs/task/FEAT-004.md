# FEAT-004 — 工程项目管理模块

- **状态：** Done

- **负责人：** L1 coordinator (l1-plan004-20260523163429)

## 范围

新增独立的 `project` 模块：以工程项目为聚合，承载成员（真实 + 外部）、工单、
采购记录与项目文件。研发阶段——接受破坏性更改，不做存量数据迁移。

模块构成：

- **`project` 核心模块**（自持表，参照 `drive`）：`projects` + 单一
  `project_members` 表，内部（真实用户）与外部（供应商 / webhook 关联）成员
  共用一张表，通过类型列区分。
- **工单（issue）**——**复用现有 `issue` item 子类型**，扩展项目归属。项目工单
  即带项目归属的 issue；个人 issue（无项目）保持原有行为。
- **`procurement`**——新增 `item` 子类型，带项目归属、默认状态流转与基于评论的
  事件日志。
- **drive `project` ownerType**——项目文件即项目所属的 drive 条目（即
  `drive.md` 中暂缓的 ownerType），权限按 `project_members` 解析，禁止从 drive
  侧删除。
- **事件收发（入站 + 出站）**——本期仅做设计；具体实现延后到未来的全局通知 /
  事件分发模块。

不删除任何模块：`issue` 是复用扩展，而非删除。

## 验收

- `bun run check` 通过（lint + 类型检查）。
- `project`、`procurement` 与扩展后的 `issue` 的服务层单测，对齐 `document`
  的覆盖形态（创建 → 组合行 + tuples、更新自增 version、软删除清理 tuples、
  成员类型 / 角色裁决）。现有个人 issue 测试保持通过。
- drive 项目所属条目：项目成员可浏览 / 上传；非成员 fail-closed；对项目条目的
  drive 删除被拒绝。
- 采购可见性：未授权成员看不到采购；PM 与已授权成员可见。
- 手动：管理员创建项目，添加一个内部成员 + 一个外部成员，将外部成员转正，
  给二者分别指派工单与采购，让采购走完默认状态集，打开由 drive 浏览器支撑的
  项目文件页签。
