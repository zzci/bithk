## Goal

Build file preview INTO the shared `FileBrowser` so the project files tab and
ship files tab (and any future consumer) get the drive-style preview dialog by
default, with no per-page wiring. Today only `drive.lazy.tsx` renders
`<FilePreviewDialog>`, so opening a file in a project/ship tab is a no-op.

## Scope

- EDIT (primary): `apps/web/src/app/routes/_app/-file-browser.tsx`
- ADD: a FileBrowser preview-open test (co-located, e.g.
  `apps/web/src/app/routes/_app/-file-browser.test.tsx`, or extend an existing
  one if present).
- Do NOT change `drive.lazy.tsx`, `$projectId.files.lazy.tsx`, or
  `-ship-files-tab.tsx` — they work unchanged once FileBrowser self-serves.

## Requirements

1. In `-file-browser.tsx`, add internal preview state, e.g.
   `const [previewEntry, setPreviewEntry] = useState<DriveEntry | null>(null)`
   and `const [previewEditing, setPreviewEditing] = useState(false)`.
2. Define an internal open handler mirroring `drive.lazy.tsx`'s `openPreview`
   (`drive.lazy.tsx:88-95`): if `isUniverSheetEntry(entry)` → route to the sheet
   editor via the existing `openSheet` (already defined at
   `-file-browser.tsx:125-128`, navigates to `/drive/sheet/$entryId`); otherwise
   `setPreviewEntry(entry)` + `setPreviewEditing(edit)`.
3. Make `onPreviewEntry?` an OPTIONAL OVERRIDE: compute one effective handler,
   e.g. `const handlePreview = onPreviewEntry ?? internalOpenPreview`. Wire it
   where the current code calls `onPreviewEntry?.(...)`:
   - `actions.onPreview` (`-file-browser.tsx:298-302`) → `handlePreview(entry)`.
   - `CreateTextFileDialog onCreate` success
     (`-file-browser.tsx:386-392`) → `handlePreview(entry, true)` (open the new
     blank file straight into edit mode).
4. Render `<FilePreviewDialog>` from `./-file-preview-dialog` ONLY when the
   parent did NOT supply `onPreviewEntry` (i.e. when FileBrowser owns preview)
   and `previewEntry` is set:
   ```tsx
   {!onPreviewEntry && previewEntry && (
     <FilePreviewDialog
       entry={previewEntry}
       open
       initialEditing={previewEditing}
       readOnly={!canManage}
       onOpenChange={open => !open && setPreviewEntry(null)}
     />
   )}
   ```
   `FilePreviewDialog` is self-contained: it fetches its own bytes
   (`httpRaw('/drive/entries/:id/content?inline=true')`), downloads via
   `downloadDriveEntry(entry)`, and renders its own version-history dialog. No
   `fetchContent` / `onDownload` props are needed in the authenticated app
   context — omit them (they default to the authenticated endpoints).
5. Add the `FilePreviewDialog` import. Keep `isUniverSheetEntry` import (add to
   the existing `@/shared/lib/api/drive` import group). Do not remove
   `onShareEntry` / existing behavior.

## Design Constraints (inherited from L2 plan)

- Drive must NOT regress: because `drive.lazy.tsx` passes `onPreviewEntry`,
  FileBrowser defers to it and does NOT render its own dialog there (the
  `!onPreviewEntry` guard). Drive keeps its single open-routing chokepoint that
  the non-FileBrowser lists (recent/favorites/trash/shares/sidebar) also use.
- Spreadsheet open path must NOT break: `.sheet` entries opened from ANY context
  go to `/drive/sheet/$entryId`; only normal files open the preview dialog.
- `readOnly={!canManage}` so viewers (project `canManageFiles` false / ship
  `canManageProject` false) get a read-only preview with no edit/save.
- Keep the diff minimal and localized to `-file-browser.tsx` + the test.
- Match existing code style (immutable state updates, double quotes, 2-space).

## Verification (run the dev app)

- Project files tab (`/projects/$projectId/files`): click an image / pdf / text
  / markdown / code file → preview dialog opens, like drive. Download +
  version-history work from it.
- A `.sheet` file opened from the project tab → opens `/drive/sheet/$entryId`
  (sheet editor), NOT the preview dialog.
- Ship files tab: same preview behavior.
- Drive page: preview STILL works; spreadsheets still open the sheet editor; no
  duplicate dialog, no console errors.
- Viewer (no manage cap): preview opens read-only (no edit/save button).
