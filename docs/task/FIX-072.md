## Goal

`POST /backup/export`, `POST /backup/export-via-token` and `POST /backup/import`
were deprecated on 2026-06-10 (PLAN-075 phase 6, "kept for one release") and
are still mounted at v0.3.13. The v1 import keeps the delete-then-insert engine
that FIX-062 declared removed, and it has no PLAN-108 format-epoch gate: only
column-shape rejection stands between a pre-reset dump and the live schema, so
a dump of an unchanged module still imports wholesale. The changelog claim that
one epoch check covers every import path is false while this route exists.

## Scope

- Unmount the three v1 routes; delete `restore.routes.ts` and its test. Keep
  `GET /backup/modules` (the web backup tab reads it) and move the per-token
  export gates (`backupExportInFlight`, `backupExportLastSuccess`,
  `tokenBucketKey`) next to their only remaining consumer, the v2 token route.
- `export.service.ts` / the v1-only parts of `restore.service.ts` stay as the
  round-trip harness five module backup tests use; header comment marks them
  test-only. Porting those tests onto the v2 archive services is a follow-up.
- Port `tests/e2e/modules/backup/restore.test.ts` onto the v2 import routes;
  delete the v1 `export.test.ts`.
- Docs: `docs/modules/backup.md`, `docs/reference/api.md`,
  `docs/develop/operations.md`, `.env.example` (+ regenerated env reference),
  `apps/api/src/config/schema.ts` comment, `docs/architecture.md`,
  `README.md`; regenerate api-routes / openapi spec / api-types; changelog
  `Removed` entry.
