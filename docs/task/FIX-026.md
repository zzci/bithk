## Goal

Make staged create-issue attachments visible and removable before submit. The
`CreateIssueDialog` already stages files and uploads them after create; add the
missing UI: a compact list of staged files at the bottom of the description
editing area, each with name (+ optional size/icon) and a remove `Button` that
drops the file from the in-memory staged list (no server call).

## Scope

- `apps/web/src/app/routes/_app/projects/-project-issues-tab.tsx`
  (`CreateIssueDialog` only): render the staged-file list + a `removeFile(index)`
  handler that does `setFiles(prev => prev.filter((_, i) => i !== index))`.
- `apps/web/src/locales/{en,zh}/projects.json`: add
  `issues.composer.removeAttachment` (remove-button aria-label), en/zh parity.

Read-only for context:
- `apps/web/src/shared/components/resource/attachment-section.tsx` (reuse the
  exported `formatFileSize` + the file-row chip styling).

### Scope addition (user-approved, 2026-06-02)

Same component, same L3: tighten the dialog's excess bottom padding. There is a
large blank gap between the sticky footer row (Create-more Switch + submit
Button) and the dialog's bottom edge. Adjust only spacing/padding utility
classes (DialogContent padding chain + the footer's `-mx-4 -mb-4` negative
margins) so the footer hugs the bottom edge with balanced padding matching the
other edges. Do not change footer contents or the staged list.

Out of scope: backend, the upload-on-create flow, `attachment-section.tsx`
edits, any other component.

## Acceptance

- Staged list shows below the description when `files.length > 0`; each row has
  name (+ size) and an `X` remove `Button` with an `aria-label`.
- Remove drops only that file in memory; pill count + list stay in sync.
- List clears after successful create (existing `reset()` unchanged).
- en/zh parity intact; `bun run check` exits 0 (mind the known `@milkdown/ctx`
  flake; `bun install` first if a fresh worktree errors 127).
