# FIX-042 Backup coverage gaps + full seed-dataset round-trip test

- Status: Completed
- Plan: -
- Owner: local-session
- Updated: 2026-06-16

## Goal

The FEAT-033 backup CLI e2e only seeded an admin + settings, so it could not
catch data lost on a real backup. Reuse the full seed dataset to prove the
round-trip is complete, and close the coverage gaps it surfaces.

## Findings (from a real seed → export → import round-trip)

Of the 8 tables not present in a backup, six are intentional and correct to
exclude — logs / transient / security state never restored: `audit_events`,
`sessions`, `auth_lockouts`, `pkce_challenges`, `totp_challenges`,
`user_totp_devices`. Two were accidental gaps:

- `global_procurement_categories` — global procurement vocabulary, the sibling
  of `global_equipment_categories` (which IS backed up via the ship
  contribution). Registered in no contribution, so it was silently dropped.
- `document_pins` — per-user pinned documents. `user_preferences` and the
  `drive_entries.favorite` flag are backed up, so per-user pins should be too.

## Scope

- `apps/api/src/modules/project/project.backup.ts`: add
  `globalProcurementCategories` (leads — no project FK).
- `apps/api/src/modules/document/document.backup.ts`: add `documentPins`
  (FK `user_id` → users, `item_id` → items; add the `users` dep).
- `apps/api/src/modules/project/project.backup.test.ts`: update the table
  snapshot.
- `tests/e2e/modules/backup/cli-roundtrip.test.ts`: new test that seeds the
  full dataset (subprocess), runs `backup:export` → `backup:import`, and asserts
  every table except the six intentional exclusions round-trips with identical
  row counts.

Out of scope: changing which transient/log tables are excluded; any schema
change (registration only).

## Acceptance

- A full seed-dataset round-trip imports with no row loss for every backed-up
  table (only the six excluded tables differ); the new e2e locks it.
- `global_procurement_categories` and `document_pins` are present after restore.
- `bun run check` passes.
