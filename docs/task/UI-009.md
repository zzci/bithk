# UI-009 Add a semantic color system to the ship detail page

- **status**: done
- **priority**: P1
- **owner**: current session
- **createdAt**: 2026-05-25 21:30

## Description

The ship detail page (hero + overview tab) renders almost entirely in neutral
grays. The theme has no semantic hues at all — `index.css` only ships
`primary`/`destructive` plus `chart-1..5`, and every chart color sits in the
same violet hue band (oklch hue 274–277). As a result information of different
kinds (lifecycle stage, status, metrics, maintenance urgency, equipment
breakdown) reads as one undifferentiated block, which is the gap against the
`backup/untitled` prototype that uses a per-lifecycle-stage palette and semantic
status colors.

Introduce a scoped color system for the ship detail page using Tailwind v4
built-in palettes (no global token changes), driven by a single typed map so
the hero, overview widgets, lifecycle stepper, and the ship list all read from
one source of truth.

Development stage, breaking changes accepted.

Acceptance criteria:

1. A single `-ship-visuals.tsx` module defines a per-`ShipLifecycleStage` style
   map (icon + chip + dot color, light/dark aware) and a `LifecycleBadge`
   component; all lifecycle badges across ships (hero, overview, profile, list)
   use it.
2. Overview quick-stats render colored icon tiles; the hero metrics carry the
   same colored icons via an extended `StatTile`.
3. The lifecycle stepper colors each stage by its own hue (done = filled +
   check, current = filled + ring, future = hollow).
4. Upcoming maintenance rows show a colored leading icon and a status-colored
   badge (degraded from the prototype's due-date/priority view — those fields do
   not exist on `ShipMaintenanceOrderView`).
5. Bound projects show a status-colored badge and a brand-colored base badge;
   equipment categories render proportional progress bars.
6. `bun run check` passes (lint, typecheck, tests, build); affected ship tests
   updated where selectors moved.
