# FIX-049 - Auth IP rate-limit loopback exemption under TRUST_PROXY=false (P2)

- Status: Planned
- Plan: [PLAN-100](../plan/PLAN-100.md)
- Campaign: `l1-bithk-audit-20260701145456`
- Owner: L3
- Created: 2026-07-01

## Summary

The auth per-IP rate limiter exempts loopback source IPs. With the default `TRUST_PROXY=false`, `getClientIp`
returns the socket peer, so a same-host reverse proxy connecting over loopback makes every auth request look
like `127.0.0.1` → IP throttling is disabled. See AUDIT-20260701.md → P2.

## Acceptance Criteria

- The loopback exemption no longer silently disables IP rate limiting in the default `TRUST_PROXY=false`
  same-host-proxy topology. Acceptable approaches (pick the smallest correct one):
  - only exempt loopback when `TRUST_PROXY=true` (loopback then legitimately means "the trusted proxy"), OR
  - drive the exemption off the resolved real IP rather than the raw peer, OR
  - at minimum, emit a boot warning when a proxy-on-loopback + `TRUST_PROXY=false` misconfig is detected.
- Legitimate local dev is not broken (document/keep dev ergonomics).
- Account-level lockouts remain intact.
- Tests cover: `TRUST_PROXY=false` peer=127.0.0.1 is still rate-limited on repeated `/login`.
- `bun run check` passes.
