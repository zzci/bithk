# FIX-065 - CSP blocks presigned S3 direct-upload PUTs and previews

- Status: Completed
- Plan: [PLAN-106](../plan/PLAN-106.md)
- Created: 2026-07-06

## Problem (user-reported, production)

With the S3 driver active, the browser's presigned direct-upload `PUT` (and
presigned-GET inline previews) target the S3 endpoint's origin. The app's
`Content-Security-Policy` (`app.ts` `secureHeaders`) only listed `'self'` +
`blob:` in `connect-src` / `img-src` / `frame-src`, so the browser blocked the
cross-origin request — the signed link "was intercepted / never succeeded".
This is why FEAT-050 direct upload failed for the owner even after the driver
was configured correctly and CORS on the bucket was set.

## Fix

- `storage/s3.ts` exposes `s3PublicOrigin()`: the presign endpoint's origin,
  derived by probing a presign at `configureS3Driver` time (exact for
  path/virtual-host/R2 addressing), refreshed on every admin storage-config
  change, null while unconfigured.
- `app.ts` CSP adds a per-request dynamic source (hono
  `ContentSecurityPolicyOptionHandler`) resolving to that origin (or a
  harmless duplicate `'self'` when unset) on `connect-src`, `img-src`,
  `media-src`, and `frame-src`.

## Verification

- `s3.test.ts`: origin is null pre-config, equals the endpoint origin
  post-config, resets on driver reset.
- `app.csp.test.ts`: the CSP header omits any S3 origin while unconfigured and
  carries it on connect/img/media/frame once S3 is configured.
- `bun run check` green.
