# FIX-050 - S3 orphan sweep continuation-token pagination (P2)

- Status: Planned

- Owner: L3

## Summary

The S3 orphan sweep lists only the first 1000 objects (`maxKeys:1000`, no continuation token), so orphaned/
aborted direct-upload blobs beyond the first page are never reclaimed on buckets with >1000 objects. See
AUDIT-20260701.md → P2.

## Acceptance Criteria

- `list` (or the sweep) iterates all pages via the S3 continuation token, so every object is considered.
- The registered-key guard stays correct at scale: a blob registered in `files` is never deleted regardless
  of which page it is on (do not narrow the `inArray` guard to a single page's keys — cross-check against the
  DB, or accumulate keys across pages before deciding).
- Bounded memory / batched deletion (do not load an unbounded list into memory without limit).
- Tests cover a >1000-object listing (fake driver returning a continuation token across two pages).
- `bun run check` passes.

## Files in Scope

- `apps/api/src/modules/file/storage/s3.ts` (`list`, ~110-111)
- `apps/api/src/modules/file/s3-sweep.ts` (sweep loop, ~29-52)
- Co-located tests: `apps/api/src/modules/file/*.test.ts`

## Design constraints

- Keep the deletion-safety property: only unregistered objects older than the TTL are deleted.
- Do not change the sweep interval/TTL semantics.
