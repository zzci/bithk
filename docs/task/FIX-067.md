# FIX-067 - CLI commands print "sonic boom is not ready yet" on exit

- Status: Completed
- Plan: [PLAN-106](../plan/PLAN-106.md)
- Created: 2026-07-06

## Problem (user-reported)

Running a CLI subcommand that opens the runtime (`script:*`, `backup:*`)
printed `error: sonic boom is not ready yet` after finishing its work. The
command's work completed; the error is exit-time noise.

Cause: `withRuntime` builds the pino logger with an ASYNC file destination
(`pino.destination({ sync: false })` → SonicBoom). A CLI process
`process.exit()`s immediately after the command returns (`index.ts:17`);
pino's on-exit auto-flush (`on-exit-leak-free` → `autoEnd` → `flushSync`) fires
before SonicBoom has finished opening its fd, so `flushSync` throws "sonic boom
is not ready yet". The long-lived server never hits this — it flushes on its
graceful-shutdown path with the fd long open.

## Fix

- `createLogger(config, { sync })`: optional synchronous destination. Sync
  opens the fd up front, so the exit-time flush is safe.
- `cli/runtime.ts` `withRuntime` builds its logger with `{ sync: true }`. The
  server keeps the async destination (throughput).

  does not throw.

  --dry-run` exit cleanly (0 / 2) with no sonic-boom error.
