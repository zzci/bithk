# FIX-068 - APP_DISPLAY_NAME env change never updates the running app

- Status: Completed
- Plan: [PLAN-106](../plan/PLAN-106.md)
- Created: 2026-07-06

## Problem (user-reported)

Setting `APP_DISPLAY_NAME` in the env and restarting did NOT change the
displayed app name (sidebar + browser tab title). There is no admin UI to
edit it either.

Cause: `seedSettingsFromEnv` wrote `app.display_name` from the env only when
the setting was `null` (first boot). After that the DB value was authoritative
and the env was ignored. Both the sidebar and the tab title (`useDocumentTitle`
→ `useBranding` → `/system/branding`) read that same DB setting, so neither
followed a later env change. (The build-time `index.html` `<title>` is only the
pre-load value; the SPA overrides it at runtime from branding.)

## Fix

- `seedSettingsFromEnv`: `app.display_name` is now env-authoritative. When
  `APP_DISPLAY_NAME` is EXPLICITLY set in the env, the setting is (re)written
  from it on every boot, so changing the env + restart updates the branding.
  When the env var is absent, keep the seed-once fallback so the schema default
  ("bit") does not clobber an existing value. No frontend change needed (the
  tab title is already dynamic via `useDocumentTitle`).

## Verification

- `app-config.test.ts`: explicit env overwrites an existing value on boot;
  unset env does not clobber an existing value.
- `bun run check` green.

## Note

There is still no admin-UI field to edit the display name; the env is the
single source of truth. If UI editing is added later, revisit the
overwrite-on-boot behaviour.
