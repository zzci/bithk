# FEAT-024 - Global roles with per-module visibility

- Status: Planned
- Plan: [PLAN-076](../plan/PLAN-076.md)
- Campaign: local
- Owner: (unassigned)
- Created: 2026-06-10

## Summary

Introduce named global roles that grant access to a configurable set of
main-area modules (documents, drive, projects, ships, contacts, and future
finance/HR). Non-admin users see and can call only the modules their role
grants; admins keep full access. Replaces today's binary admin-vs-everything
module visibility.

## Acceptance Criteria

- `global_roles` table with `modules` JSON set, system default role seeded
  by boot backfill; `users.globalRoleId` FK with `NULL` → default role.
- Existing users keep exactly today's visibility after migration (default
  role grants all current main-area modules).
- Backend answers requests to a hidden module's routes with 404 for
  non-admin users (fail-closed concealment per decision 003); admins
  bypass. A test asserts every main-area route prefix is claimed by a
  module key or explicitly ungated.
- `/account/me` returns the resolved `modules` list.
- Sidebar, route guards, and command palette/search only expose visible
  modules; deep links into hidden modules redirect to `/overview`.
- Admin Roles page supports role CRUD with a module checkbox editor; Users
  admin page assigns a user's global role.
- Global search results are filtered to visible modules.
- en/zh i18n complete; focused API and web tests; `bun run check` passes.
