## Summary

REFACTOR-037 catalogued spec-vs-server describeRoute gaps (9 `TODO(spec)` markers in
`apps/web/src/shared/lib/api/`). Fix the backend annotations so the generated spec matches what
the server actually returns, root-fix the spec generator's dangling recursive $refs, regenerate
spec + types, and replace the web-side narrow local workarounds with the now-correct generated
types.

## Gap list (fix in backend describeRoute/zod schemas)

1. account: GET /account/users pagination meta (totalPages etc.) undocumented; `AccountUser.groups`
   (`{id,name}[]` attached by users.service) absent from the schema; GET endpoints marked
   TODO(spec) in `api/account.ts`.
2. system: `SystemVersion.lode` typed `z.unknown()` — describe the structured LodeSummary
   (`api/system.ts`).
3. favorites/overview: `status` fields plain string — add project/issue/procurement enums;
   `FavoriteProjectItem.code` nullability — verify server and mark `.nullable()` if so
   (`api/favorites.ts`).
4. pins: `PinnedItem.type`/`status` missing enums.
5. cron: GET /cron/actions `actions` typed `unknown[]` — add the catalog-entry schema
   (`api/cron.ts`).
6. backup: ExportJobView `state`/`blobsMode`/`progress`/`artifacts` and ImportJobView (+ upload
   201) `state`/`report`/`result` typed string/unknown — describe real shapes (`api/backup.ts`).
7. ships: GET /ships/{shortId}/projects `status` enum missing; `tags[].usageCount` inconsistent
   with getProjects rows.
8. procurement: list query spec lacks `tagIds`/`page`/`limit` params the frontend sends.
9. account: /account/assignable-users `isVirtual` should be required (server always returns it).
10. issue references: `refType` missing enum (`worklist|url|document`).
11. project: `ProjectView.code` missing `.nullable()`.
12. GENERATOR ROOT FIX: `apps/api/scripts/gen-api-spec.ts` emits recursive $refs to
    `#/components/schemas/__schemaN` that are never defined (/policy/expand). Fix the generator
    to emit valid components; then remove the corresponding hoisting workaround in
    `scripts/gen-api-types.ts` if it becomes dead.

Explicitly NOT gaps (leave alone): share POST /shared/{token} polymorphic `data` (registry
polymorphism — content narrowings stay hand-written in web); dropped `objectName` /
worklist-reference `category` (backend never returns them; already removed web-side).

## Completion Notes (2026-07-04)

- All 12 gaps resolved at the describeRoute/zod schema level; implemented in commit on
  branch `bkd/r7hkr82d`. `bun run check` EXIT 0 (api 2019 pass / web 924 pass).
- Gap 11 (ProjectView.code `.nullable()`) is NOT a real bug: `projects.code` is
  `NOT NULL` (auto-generated `p-<shortId>` when omitted, `createProject`), so the
  server never returns null — schema left as `z.string()`.
- Gap 3 code nullability: same finding for `FavoriteProjectItem.code` — non-null.

  `projectTagSchema` was under-documenting the runtime `ResourceTagUsageView`).

  outside the query validator by `parseTagIds`/`parsePageQuery`; adding them to the
  validator could change 422 semantics).
- Generator: `$defs` hoisting moved from `scripts/gen-api-types.ts` (removed) into
  `apps/api/scripts/gen-api-spec.ts`; spec is self-contained (`__schema0` defined in
  components.schemas, 0 dangling refs, 0 `$defs`).
- `ISSUE_STATUSES` now lives in `apps/api/src/modules/issue/schema.ts` (mirrors the
  PROJECT/PROCUREMENT/SHIP statuses placement) for overview/item reuse.
- `docs/reference/api-routes.md` regenerated byte-identical (it lists routes/summaries
  only), so it carries no diff.
