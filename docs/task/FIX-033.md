## Requirements

Generic component API (discriminated union on mode):
```
interface FilterOption { value: string; label: string; count?: number }
type FilterDimension =
  | { key: string; label: string; mode: "single"; options: FilterOption[]; value: string | null; onChange: (v: string | null) => void; defaultValue?: string }
  | { key: string; label: string; mode: "multi"; options: FilterOption[]; value: string[]; onChange: (v: string[]) => void }
interface ListFilterProps { dimensions: FilterDimension[]; className?: string }
```
- Single 筛选 trigger Button → dropdown/popover (use existing
  `@/shared/components/ui/dropdown-menu`) listing options grouped by dimension
  with section labels, aria-checked items, optional counts.
- Selected options → removable × chips to the RIGHT (real Button remove,
  aria-label). Single-select default value may render non-removable / as active.
- a11y: trigger Button, chip remove Button + aria-label, items aria-checked.

Projects-list adoption (index.lazy.tsx, current filter row ~105-153):
- 状态 dimension: single, options active/archived (labels from
  `status.active`/`status.archived`) with counts (activeCount/archivedCount),
  default active. Wire to existing `filter` state (`__active__`/`__archived__`)
  + `setPage(1)`.
- 标签 dimension: multi or single per current behavior. NOTE today's projects
  list is SINGLE-select tag (`selectedTagId` via `filter` holding a tagId). Keep
  the SAME observable behavior: selecting a tag filters by it; the status and tag
  are mutually exclusive in the current `filter` state machine. Either preserve
  the single `filter`-string model (status value OR a tagId) mapped through the
  two dimensions, or refactor cleanly while keeping identical list results via
  `projectsFilterToQuery`. Do NOT change `projectsFilterToQuery` semantics.
- Keep the search box unchanged.

i18n: add `筛选`/`Filter` trigger label + dimension section labels (reuse
`status` and `list.tagFilterMore="Tags"`/标签 where possible). en + zh parity.
