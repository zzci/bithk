# UI-027 Unify file/drive upload UX (global queue, folder grouping, attach-from-drive)

- Status: Completed
- Plan: [PLAN-088](../plan/PLAN-088.md)
- Owner: local-session
- Updated: 2026-06-19

## Goal

Make upload progress and drive-file reuse consistent everywhere a user attaches
files. Previously the upload-queue panel only rendered on the drive page, so
uploads started from a project or ship surface showed no progress; and there was
no way to attach an already-stored drive file to a resource without re-uploading
its bytes.

## Scope

Delivered across six lanes:

- **A — shared queue** (`shared/components/file/upload-queue.ts`,
  `upload-queue-panel.tsx`): the drive upload queue store, uploader hook, and
  bottom-right panel were promoted out of the drive feature into
  `shared/components/file` so any surface can enqueue and render progress.
- **B — backend attach-from-drive** (`document` / `issue` / `procurement` /
  `hr` routes): `POST /:id/attachments/from-drive` registers a new
  `file_reference` to a drive entry's already-stored blob via
  `file.service.addReference` (no re-upload). The actor's READ access on the
  drive entry is verified server-side (`assertEntryCapability`).
- **C — folder grouping** (`upload-queue-panel.tsx`): tasks carry
  `relativePath`; the panel groups them by top-level folder with a per-folder
  file count and aggregate progress, plus an overall summary. Upload strings
  moved to the `common` namespace.
- **D — global mount** (`app/routes/_app.tsx`): `UploadQueuePanel` is mounted
  once in the app layout so progress shows regardless of where an upload began.
- **E — Choose-from-Drive** (resource attachment areas): a "Choose from Drive"
  button opens the existing `-drive-file-picker` and calls the new from-drive
  endpoint to attach without re-uploading.
- **F — tracking + tests** (this task): PMA docs, a `UploadQueuePanel` render
  test (folder grouping / summary / preparing placeholder), and a backend
  from-drive route test (happy path refcount bump + permission denial).

## Acceptance

- Upload progress appears on every surface, not only the drive page.
- A drive file attaches to a document/issue/procurement/HR record without
  re-uploading: a new `file_reference` is added and the blob refcount is bumped,
  with no new blob row.
- Attaching an entry the actor cannot read is rejected (404/403) with no
  reference added.
- `bun run check` EXIT 0.
