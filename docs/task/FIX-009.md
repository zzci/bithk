## Acceptance

- Issue list path uses a JOIN (`items ⋈ issueDetails`), resolves the project
  short id once per page, batches assignee tuples + tags; no per-row N+1.
- Issues tab issues ONE list request grouped client-side, not 5.
- Project-list count queries use `limit:1` (or a counts endpoint), not full
  pages.
- `searchIssues` batched; `loadResourceTagsByResource` no correlated subquery.
- Migration adds `project_members.user_id` index.
- Tabs memoized where cheap.
- `bun run check` EXIT=0.
