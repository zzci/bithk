# UI-032 - Project Files tab sizes itself with a magic number instead of filling the tab area

- Status: Proposed
- Plan: -
- Created: 2026-08-28

## Goal

The project Files tab does not fill its container. It sizes the drive surface
with a hardcoded viewport subtraction
(`apps/web/src/app/routes/_app/projects/$projectId.files.lazy.tsx`):

```tsx
<div className="-mx-4 h-[calc(100svh-18rem)] min-h-[24rem]">
```

`18rem` is a guess at the combined height of the app header, the project detail
header and the tab bar. Whenever that guess is wrong the tab either leaves dead
space below the file list or pushes the page into a second scrollbar — and it
is wrong more often after PLAN-108, because the detail header now varies with
the project (a ship project renders extra identity rows, and the tab bar can
wrap once six sections are mounted).

The standalone drive page does not have this problem: it uses a real flex
shell (`-mx-6 md:-my-4 md:h-svh md:flex-row`, `drive.lazy.tsx:159`).

## Scope

Replace the magic height with a flex fill. The container chain already
supports it: `_app.tsx:123` renders `<main class="flex min-w-0 flex-1
flex-col overflow-auto …">`, so the project detail root and the wrapper around
its `<Outlet />` (`$projectId.lazy.tsx:195`) need `flex-1 min-h-0` for the tab
body to claim the remaining height with `h-full`.

Check the sibling tabs while there: whatever container change lands must not
regress the issues / procurement / overview / equipment / worklist tabs, which
currently rely on the page scrolling rather than an inner scroll area.

Out of scope: restyling the file browser itself, and any change to the
standalone `/drive` page.

## Verification

- The Files tab fills the area between the tab bar and the viewport bottom with
  no dead space and no nested scrollbar, at 1280x800 and 1440x900, for both a
  general project (4 tabs) and a ship project (7 tabs, header with identity
  rows).
- No `calc(100svh-…)` magic number remains in the project tab routes.
- The other project tabs scroll and lay out exactly as before.
- `bun run check` EXIT 0.
