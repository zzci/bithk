# FIX-038 Fix production secure-cookie deletion

- Status: Completed
- Plan: -
- Owner: local-session
- Updated: 2026-06-09

## Goal

Packaged production runs throw `__Secure- Cookie must have Secure attributes`
when auth routes delete production-prefixed cookies without the `Secure`
attribute. Fix the production cookie deletion path without changing cookie
names or login semantics.

## Scope

- `apps/api/src/modules/account/auth/auth.routes.ts`
- Focused auth route tests for production `__Secure-` cookie deletion.

Out of scope: session cookie naming, OAuth provider behavior, deployment
configuration, unrelated auth refactors.

## Acceptance

- Production OAuth callback cleanup deletes the `__Secure-oauth_state` cookie
  with `secure: true` and the configured base path.
- Production TOTP cleanup paths continue deleting `__Secure-totp_pending` with
  `secure: true`.
- Focused tests cover the production `__Secure-` deletion behavior.
- Focused auth tests pass.

## Notes

- 2026-06-09 - Investigation found the likely root cause in OAuth state cookie
  deletion: the callback deletes the environment-selected cookie with
  `{ path: "/" }`, which is invalid for the production `__Secure-oauth_state`
  name under Hono's cookie validation.
- 2026-06-09 - Fixed OAuth state cookie deletion to reuse the configured cookie
  path and set `secure: true` in production. Added a production callback
  regression test. Focused auth tests and `bun run check` passed.
