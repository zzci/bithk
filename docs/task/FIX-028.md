## Goal

Make the pinned tag chips in `ProjectTagFilter` responsive to the container
width. Currently a fixed `PINNED_COUNT = 5` most-used tags pin as inline toggle
chips; the rest feed the "标签" selector. Change the EFFECTIVE pinned count to
adapt to available width: when the row narrows, show FEWER pinned chips (drop
the least-used; keep the most-used first), down to 0 with no room; 5 stays the
MAX when wide. Any top-5 tag that doesn't fit falls into the "标签" dropdown
with the other non-pinned tags — nothing is lost. Public props UNCHANGED.

## Implementation

1. Add a wrapper `ref` and a `ResizeObserver` that tracks the container's inner
   width. Store an effective fit count in state.
2. A minimal local fit helper computes how many of the top-5 pinned chips fit a
   measured width, reserving room for the always-present "标签" selector trigger
   (and account for the gap). Keep it small and unit-tested. (Reintroduce a
   tiny version of the deleted `-project-tag-filter-logic.ts` — e.g.
   `-project-tag-filter.fit.ts` exporting a pure `pinnedFitCount(...)`, or keep
   it inline if cleaner; if a separate file, co-locate a `.test.ts`.)
3. `const count = Math.min(effective, tags.length)` then
   `pinned = tags.slice(0, count)`, `rest = tags.slice(count)`. The rest list
   already feeds the dropdown/combobox (minus selected) — no other change.
4. Clamp count to `[0, min(5, tags.length)]`. `PINNED_COUNT = 5` is the MAX.
5. **Fallback:** when there is no `ResizeObserver` (SSR) or no measured width
   yet (width 0, e.g. jsdom), render up to the MAX (5, clamped to tag count).
   Tests run in jsdom with no layout, so the default MUST be max — existing
   component tests AND consumer tests (`-project-issues-tab.test.tsx` overflow
   cases) rely on all 5 pinning when unmeasured.
