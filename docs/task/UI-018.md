# UI-018 Refine collapsible project work-order grouped list

- Status: Done
- Plan: [PLAN-026](../plan/PLAN-026.md)
- Owner: L2 dispatch rwd83bpm / L3 ztjzlax5
- Updated: 2026-05-28

## Goal

Refine the project work-order tab so status groups are collapsible, toolbar
filtering remains available, and grouped rows feel lighter and clearer than a
heavy table.

## Scope

- `apps/web/src/app/routes/_app/projects/-project-issues-tab.tsx`
- `apps/web/src/app/routes/_app/projects/-project-issues-tab.test.tsx`
- Direct project locale keys only if needed for accessible labels.

Out of scope: backend APIs, schema, dependency changes, global tags work,
project overview, unrelated list/table components, and broad terminology
changes.

## Acceptance

- Status groups can collapse and expand.
- Expanded/collapsed state remains intuitive while search and filters change.
- The toolbar keeps search, create, and basic non-status filtering.
- Statuses remain visible as grouped sections, not top status tabs.
- Empty status groups are hidden after active search/filter.
- Status groups use the requested product order/labels where supported by
  existing data: todo, in progress, pending review, done, plus cancelled only
  when populated.
- Rows are compact, scannable, responsive, and visually lighter than a table.
- Row content reads left-to-right as title, priority, assignee, and due date.
- Row navigation, create, edit/view behavior, pinning, and metadata remain.
- Pinned rows are not shown in a separate section and are not duplicated; the
  visible list remains organized by status groups only.
- Focused tests cover collapse/expand, filtering, search/create presence, and
  row rendering.
- Focused verification runs; `bun run check` is attempted.
