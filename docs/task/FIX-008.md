# FIX-008 Project role / authz hardening (Campaign A)

- Status: In Progress
- Plan: [PLAN-044](../plan/PLAN-044.md)

## Goal

Close the role/member privilege-escalation surface: delegated admin
permissions must not amplify into full ownership, and the project must keep at
least one Owner.

## Findings

| ID | Sev | Title | Location |
| --- | --- | --- | --- |
| 02-F1 | P1 | `members.manage` can self-assign Owner/system role → full takeover | `project.routes.ts:340-360` |
| 02-F2 | P2 | `roles.manage` allows unbounded capability escalation on custom roles | `project.roles.ts:158-200` |
| 02-F3 | P2 | No safeguard against demoting/removing the last Owner (lockout) | `project.service.ts:604-636` |
| 02-F4 | P3 | Member create/update accept arbitrary `userId` → 500 not 4xx | `project.routes.ts:79-97`; `project.service.ts:577-629` |

## Acceptance

- `addMember`/`updateMember` reject assigning the Owner/system role to a member
  (incl. self) → clean 4xx; covered by a unit test.
- `roles.manage` cannot grant a capability the caller does not already hold (or
  the dangerous caps are restricted to Owner/app-admin) → unit test.
- A "≥1 Owner must remain" guard blocks demoting/removing the last Owner → 4xx;
  unit test.
- Member create/update with a non-existent/duplicate `userId` returns a 4xx, not
  a 500; unit test.
- `bun run check` EXIT=0.
