# FIX-019 Unify status icon — create dialog reuses StatusIcon

- Status: In Progress
- Plan: [PLAN-046](../plan/PLAN-046.md)
- Owner: BKD L3 (combined with FIX-018)
- Campaign: l1-75ymcfnr-pridef-20260602013633

## Goal

Render issue status through exactly ONE icon component app-wide. The create-issue
dialog status selector must reuse the same `StatusIcon` glyph the list uses,
instead of its own separate colored dot.

## Scope

- `apps/web/src/app/routes/_app/projects/-project-issues-tab.tsx` only:
  - Delete the `STATUS_DOT` map (`:80`).
  - Status selector trigger (`:663`): replace the
    `<span className={cn("size-2 rounded-full", STATUS_DOT[status])} />` with
    `<StatusIcon status={status} label={t(\`issues.status.${status}\`)} />`.
  - Dropdown items (`:670`): replace the per-item dot with
    `<StatusIcon status={s} label={t(\`issues.status.${s}\`)} />`.
  - `StatusIcon` (`:133`) and `STATUS_ICON_TINT` (`:71`) stay as the single
    source. Adjust selector spacing/gap only if the glyph visually needs it.

Scan confirmed `STATUS_DOT` / status-as-dot exists nowhere else (procurement
create has no status dot).

Out of scope: priority default/none (FIX-018); status enum; `status-colors.ts`.

## Acceptance

- Create-dialog status selector (trigger + every dropdown item) shows the
  `StatusIcon` glyph, identical to the list section bar / rows.
- `STATUS_DOT` is gone; no plain status dot remains anywhere.
- Status enum and colors unchanged.
- `bun run check` exits 0 (mind the known `@milkdown/ctx` flake).
