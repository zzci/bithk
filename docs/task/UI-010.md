# UI-010 Unify modules onto a global semantic color system

- **status**: done
- **priority**: P1
- **owner**: current session
- **createdAt**: 2026-05-25 22:30

## Description

UI-009 gave the ship module a rich color system, but it was scoped: it hard-codes
Tailwind palette classes inside `-ship-colors.ts` (violet/amber/cyan/emerald/
indigo/slate) instead of theme tokens. Meanwhile the global `index.css` ships a
monochromatic violet `chart-1..5` ramp that nothing consumes, and projects /
contacts still render every status, visibility, and tag chip in neutral gray
(`Badge variant="secondary" | "outline"`). The result: ship looks alive, the rest
of the app looks dead, and there is no single source of truth for color.

Introduce one global semantic color token layer (light/dark dual-channel, blue
`primary` unchanged) and route every module through it — including ship, which
drops its hard-coded Tailwind classes in favor of the global tokens.

Development stage, breaking changes accepted.

### Token set

New tokens (each with a `-foreground`), plus reuse of existing `destructive` /
`muted`:

| token | hue | meaning | consumers |
| --- | --- | --- | --- |
| `success` | emerald | in service / active / done | ship in_service·active, issue done, project active |
| `warning` | amber | building / open | ship building, issue open |
| `info` | cyan | sea trial / in progress | ship sea_trial, issue in_progress |
| `accent-design` | violet | design stage (categorical) | ship design |
| `accent-maint` | indigo | maintenance stage (categorical) | ship maintenance |

Consumption uses the shadcn idiom — token + opacity — so one class string covers
both themes (the token flips under `.dark`):
`badge = bg-success/10 text-success`, `dot = bg-success`, `ring = ring-success/25`.

Acceptance criteria:

1. `index.css` defines `success`/`warning`/`info`/`accent-design`/`accent-maint`
   (+ foregrounds) under `:root` and `.dark`, mapped in `@theme inline`; `chart-1..5`
   refreshed to the shadcn official multi-hue palette (light + dark).
2. `-ship-colors.ts` reads global tokens only; no `bg-emerald-*` / `dark:` palette
   pairs remain. Lifecycle, ship status, and issue status all map to the table above.
3. projects status badges and contacts visibility/confidential badges consume the
   global tokens instead of `secondary`/`outline` gray.
4. A `docs/decisions/` entry records the semantic + categorical tokens as a local
   extension (shadcn ships no official success/warning/info).
5. `bun run check` passes (lint, typecheck, tests, build); affected ship / project /
   contact tests updated where color selectors moved.
