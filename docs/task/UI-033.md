# UI-033 - Remove the sidebar "Ships" entry

- Status: In Progress
- Plan: [PLAN-108](../plan/PLAN-108.md)
- Created: 2026-08-31

## Goal

PLAN-108 kept a sidebar "Ships" entry as a preset link to
`/projects?section=ship-profile`, on the reasoning that the fleet is a frequent
destination and the link costs nothing in the data model.

In use it does cost something: it reads as a module that still exists. Ships
were folded into projects — no `ships` table, no `/ships/*` routes, no `ships`
nav module or PAT scope, no `ship` tag type — but a top-level sidebar entry
labelled "Ships" tells the user otherwise. Conceptual clarity beats saving one
click; remove it.

The `/projects?section=ship-profile` filter itself stays. The fleet is reached
by opening Projects and filtering, like any other section.

## Scope

- Delete `apps/web/src/app/routes/_app/-ships.nav.ts`.
- Remove its import and its entry from the sidebar registry
  (`apps/web/src/shared/components/sidebar/registry.ts:7,20`).
- Remove the now-orphaned `nav.ships` label from `common.json` in both locales
  (`en/common.json:63` and its `zh` counterpart) — verify with `git grep` that
  nothing else reads it before deleting.
- Update `apps/web/src/shared/components/sidebar/registry.test.ts`, which pins
  the exact nav key order (`registry.test.ts:13`) and asserts the ships entry's
  target (`registry.test.ts:32`).

Out of scope: the `section` filter on the projects list, the `ships` i18n
namespace (it still holds the ship-section labels: profile, equipment,
worklist, form fields), and the `Ship` icon, which the project list and cards
still use to mark ship projects.

## Verification

- `git grep -n "shipsNav"` returns nothing.
- The sidebar renders without a Ships entry; Projects is still present and the
  remaining key order matches the updated test.
- `/projects?section=ship-profile` still filters the list to ship projects when
  navigated to directly.
- No orphaned i18n key: the repo's own i18n check passes and reports no unused
  `nav.ships`.
- `bun run check` EXIT 0.
