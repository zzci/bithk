# UI-023: Project role create/edit in-page editor (dropdown + permissions table)

- Status: In Progress
- Plan: [PLAN-063](../plan/PLAN-063.md)

## Problem

The project role create/edit flow uses `RoleDialog`, a modal `Dialog` inside
`-project-settings-roles.tsx`. But the Roles tab itself renders inside
`ProjectSettingsDialog` (a modal), so creating/editing a role opens a
modal-within-a-modal. User feedback: too many nested dialogs is unfriendly.

## Goal

Replace the `RoleDialog` modal with an IN-PAGE editor inside the Roles settings
tab:

1. A dropdown (`Select`) to choose which role to edit + a "+ New role" entry;
   selecting loads that role into an inline editor (no modal).
2. An inline TABLE of permissions: rows = capability modules
   (Issue / Procurement / Files tiers) + Administration caps; cells = the
   existing tier controls + admin `Switch`es. Reuse `buildCapabilities` and the
   `derive*Tier` helpers.
3. Inline Name input + Save / Delete. Same hooks
   (`useCreateProjectRole` / `useUpdateProjectRole` / `useDeleteProjectRole`),
   same toasts, same validation. Keep `ConfirmDeleteDialog` for delete.

## Acceptance Criteria

- [ ] Role create/edit is IN-PAGE — no nested `Dialog` for create/edit;
      `RoleDialog` removed with no dead imports left.
- [ ] Dropdown selects the role to edit and includes a "+ New role" option;
      selection drives the inline editor (create vs edit mode).
- [ ] Permissions set via an inline table (module rows + tier/admin controls),
      reusing `buildCapabilities` / `derive*Tier`; capability semantics
      unchanged.
- [ ] Create / update / delete identical to today (same hooks, toasts,
      `name.trim()` guard, preset quick-fill); `ConfirmDeleteDialog` retained.
- [ ] Owner/Guest system roles read-only (caps shown, not editable/deletable);
      preset/custom roles editable.
- [ ] i18n en/zh parity — reuse keys; any new inline label present in both
      `locales/en/projects.json` and `locales/zh/projects.json`.
- [ ] `-project-settings-roles.test.tsx` updated for the in-page flow and
      passing.
- [ ] `bun run check` EXIT=0 (modulo the known @milkdown/ctx teardown flake).
