# UI-020: Present the project owner role and simplify role settings

- Status: Done
- Owner: web
- Plan: PLAN-033
- Created: 2026-05-28

## Problem

The highest, system, full-capability project role is seeded and shown as
"Project Manager", and the role-settings UI renders its full capability badge
list. Because this role always holds every capability and is capability-locked,
the badge list is noise, and the "Project Manager" label does not convey that it
is the owning, top-level role. Users should see it as "Project Owner" with no
capability detail, while custom roles keep their full capability listing.

## Acceptance Criteria

- [x] The seeded system role source string is "Project Owner".
- [x] Role settings render the system role as "Project Owner" (via i18n) and omit
      its capability badge list / "no capabilities" text.
- [x] Custom (non-system) roles still show their capability badges unchanged, and
      create/edit/delete management is preserved.
- [x] Members tab role selector and read-only role label present the system role
      as "Project Owner".
- [x] Authorization semantics are unchanged: the system role still holds all
      capabilities, stays undeletable, and is capability-locked.
- [x] `roles.owner` label added to en/zh locales.
- [x] Focused frontend and backend tests cover the rename and the hidden badges.
