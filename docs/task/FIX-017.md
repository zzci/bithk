## Goal

Bring `CreateIssueDialog` (`-project-issues-tab.tsx:498-699`) up to the
Linear-style target layout, implementing ONLY the gaps versus the current
composer (do not rebuild what already matches).

## Scope

- `apps/web/src/app/routes/_app/projects/-project-issues-tab.tsx`
  (`CreateIssueDialog` region only).
- `apps/web/src/locales/{en,zh}/projects.json` — new strings in BOTH namespaces
  with key parity (a parity guard exists).
- Focused test for the dialog where practical.

Out of scope: `priority-signal.tsx` (FIX-016 owns it; the priority pill inherits
the new icon for free), backend, other modules. Serialized AFTER FIX-016 merges.

## Target gaps to implement

Current composer already has: borderless title input, borderless markdown-ish
textarea, a wrapping pill row (status / priority / assignee / due-date
`DropdownMenu` pills), sticky footer with Cancel + Create. Add/adjust:

- **Header breadcrumb**: `{projectName} › 手动创建` (manual create) at top, with
  an expand/maximize icon button and a close (×) icon button top-right.
- **Title placeholder** `issue 标题`, **description placeholder** `添加描述...`
  (keep markdown-capable consistent with the existing editor).
- **Pill row**: keep status / priority / assignee / due date; add a `项目`
  (project) pill that reflects the current project **read-only** (issues are
  project-scoped — do NOT add a fake project picker) and an overflow `...` pill
  only if there are real extra fields. Equal-height rounded outline pills.
- **Priority dropdown**: lists the priorities with the NEW icon (from FIX-016) +
  label and a check mark on the selected item (radio item already provides the
  selection indicator).
- **Footer bar**: left = attachment (paperclip) icon button; right cluster =
  `切换到智能体` toggle, `继续创建` toggle, primary `创建 issue` button.
  - `继续创建` is **functional**: when on, keep the dialog open and reset the
    form after a successful create instead of closing.
  - `切换到智能体` is presentational for layout parity — there is no
    agent-creation backend; render it as an inert/disabled toggle (commented as
    future) rather than wiring speculative behavior.

## i18n

Add new keys to both `en` and `zh` `projects` namespaces (suggested, L3 may
adjust while keeping parity): manual-create breadcrumb, `项目`/no-project pill,
`切换到智能体`, `继续创建`, `创建 issue`, paperclip aria-label, expand/close
aria-labels. Reuse existing keys where adequate (e.g. status/priority/assignee/
due-date field labels).
