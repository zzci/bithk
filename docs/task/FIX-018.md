# FIX-018 Priority default low (no none level) across create paths

- Status: Planned
- Plan: [PLAN-046](../plan/PLAN-046.md)
- Owner: BKD L3 (combined with FIX-019)
- Campaign: l1-75ymcfnr-pridef-20260602013633

## Goal

Make `low` the create default for priority everywhere and remove the
display-only `none` fallback, keeping priority a strict 4-level union
`low|medium|high|urgent` (`low` = default AND lowest).

## Scope

- Frontend create defaults:
  - `apps/web/src/app/routes/_app/projects/-project-issues-tab.tsx:528,560`
    (`useState<IssuePriority>` + reset) `medium` → `low`.
  - `apps/web/src/app/routes/_app/projects/-project-procurement-tab.tsx:380,396`
    (`useState<ProcurementPriority>` + reset) `medium` → `low`.
- `apps/web/src/shared/components/priority-signal.tsx`: remove `Minus` import,
  `PriorityDisplay` type, `none` `PRIORITY_META` entry, and the
  `?? PRIORITY_META.none` fallback; type map + `PriorityChip` as `Priority`.
- Backend defaults:
  - `apps/api/src/modules/issue/schema.ts:31` `.default("medium")` → `low`.
  - `apps/api/src/modules/issue/issue.service.ts:134,223` `?? "medium"` → `low`.
  - `apps/api/src/modules/procurement/schema.ts:41` `.default("medium")` → `low`.
  - `apps/api/src/modules/procurement/procurement.service.ts:213` `?? "medium"` → `low`.
- Tests: update assertions/DDL that expect a `medium` default to `low`:
  `apps/api/src/modules/issue/issue.test.ts:115,208`,
  `apps/api/src/modules/procurement/procurement.routes.test.ts:217` (+ body).

Out of scope: adding a selectable `none` level; status icon/dot (FIX-019);
status enum/colors. Dev phase — breaking changes allowed, no migration backfill.

## Acceptance

- New issues & procurements created without an explicit priority default to `low`
  (backend), and the create dialogs preselect `low`.
- `priority-signal.tsx` has no `none` handling and stays `react-refresh`-safe.
- Backend tests reflect `low` and pass.
- `bun run check` exits 0 (mind the known `@milkdown/ctx` flake).
