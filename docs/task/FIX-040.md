# FIX-040 Realign lode upgrade integration with breaking lode spec

- Status: Completed
- Plan: [PLAN-082](../plan/PLAN-082.md)
- Owner: local-session
- Updated: 2026-06-15

## Goal

The upgrade integration (PLAN-070/071) was written against an older lode. The
current lode `lode/v1` spec made breaking changes the integration no longer
satisfies, so a released artifact cannot launch and the readiness signalling no
longer follows lode's convention. Realign the release manifest, operator
config, CI validation, and the in-app readiness/prepare handshake with the
current spec, and extract the integration into a reusable `lode` module.

## Scope

- `scripts/package.ts`: manifest asset `entry` -> `run`/`exec`; drop `min_lode`.
- `deploy/lode.toml`: remove `[update].entry`; `[command].run` -> full launch
  command; add a finite `[supervise].prepare_timeout` safety net.
- `.github/workflows/release.yml`: validate `run`/`exec` instead of `entry`.
- Extract `apps/api/src/lode-state.ts` into a reusable `apps/api/src/lode/`
  module (state I/O, readiness, prepare watcher, summary), decoupled from app
  internals via injected `probe`/`onPrepare` callbacks.
- Readiness via the `state.ready` field convention `{LODE_INSTANCE}-{phase}`:
  report serving with phase `-0` gated on a real DB probe; watch for lode's
  prepare prompt `-1`, run a checkpoint/flush, ack `-2`; phase-aware summary.

Out of scope: artifact signing (`sig`/`key_id`/`trusted_keys`), zero-downtime
`reuseport-overlap`/`socket-activation` restart modes, GitHub Enterprise source.

## Acceptance

- `bun run package` emits a `lode/v1` manifest whose asset carries
  `run = "bun index.js"` and `exec = "bun run"`, with no `entry`/`min_lode`.
- The release workflow's manifest validation passes against the new asset shape.
- `deploy/lode.toml` contains no removed keys and launches via `bun index.js`.
- Under lode, the app reports `state.ready = {LODE_INSTANCE}-0` only after the
  DB probe succeeds, acks staged-update prompts (`-1` -> `-2`), and the
  `/system/version` summary reports readiness/phase from the phased token.
- The `lode` module has no import of app DB/cron internals; behaviour is
  injected by the caller.
- Focused unit tests cover token phase parsing, probe-gated readiness, the
  prepare watcher ack, and summary phase reporting.
- `bun run check` passes.
