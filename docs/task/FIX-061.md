# FIX-061 - Import option: wipe existing data before merge (conflict-free restore)

- Status: In Progress
- Plan: -
- Campaign: single BKD issue, worktree mode (depends on FIX-060, cut after its merge)
- Created: 2026-07-05

## Summary

User-approved (2026-07-05): add a "wipe existing data first" option to the v2 backup import so a
restore into a populated instance cannot conflict at all. Replace mode stays as-is but is
effectively unusable across the v0.2.0 baseline collapse (journal exact-match gate) — wipe+merge
covers that scenario with the tolerant mapping engine instead.

## Design

1. **Option plumbing**: `wipeExisting: boolean` (default false) on the v2 import apply —
   `import-v2.routes.ts` schema, `ImportApplyOptions`, CLI `backup:import --wipe`, web admin
   import panel checkbox (i18n en/zh) with a destructive-action confirm.
2. **Semantics**: inside the SAME transaction as the merge apply, first delete all rows from
   every registry table in delete order (children before parents; reuse the registry's existing
   delete-order machinery), then run the tolerant merge engine (post-FIX-060). Cross-schema
   archives work (mapping tolerance); no unique-key collisions remain, so imports cannot
   conflict. `defer_foreign_keys` already covers cycle deletes.
3. **Lockout guard**: with wipe enabled, require the archive to contain at least one active
   admin; match the importing actor by id OR email/oauthSub for the v1-parity session-revocation
   snapshot. CLI (synthetic actor) requires only the at-least-one-active-admin check.
4. **Files/blobs**: after a wipe+merge that restored the `files` table, run the same
   reconciliation/quarantine pass replace mode uses.
5. **Dry-run parity**: dry-run with wipeExisting reports what apply would do (deleted-row counts
   per table + the merge report) without committing.

## Acceptance Criteria

- Wipe+merge into a populated DB: completes with zero `skippedDuplicate`/`remapped` (nothing to
  collide with), `PRAGMA foreign_key_check` clean, old rows gone, archive rows present.
- Wipe+merge of a v0.1.9-era archive into the v0.2.0 baseline works (no journal gate).
- Lockout guard: archive without an active admin is refused before any deletion happens.
- Without the flag, behavior is byte-identical to current merge (regression tests untouched).
- Dry-run report matches apply outcomes; UI checkbox has a confirm step; `bun run check` EXIT 0.
