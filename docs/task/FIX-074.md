# FIX-074 - Server request-body cap silently undercuts the backup import cap

- Status: In Progress (investigation; awaiting proposal approval)
- Plan: [PLAN-111](../plan/PLAN-111.md)
- Owner: audit-remediation/session-2026-09-01
- Created: 2026-09-01

## Goal

`apps/api/src/index.ts` sets `Bun.serve` `maxRequestBodySize` to
`MAX_UPLOAD_BYTES + 64 KiB` (about 200 MB by default) while
`BACKUP_IMPORT_MAX_ARCHIVE_BYTES` defaults to 2 GiB and is documented as the
import cap. Any v2 archive or blobs.tar.gz above the server cap is refused
with a bare 413 before the route's own checks run, so the documented cap is
unreachable.

## Scope

- `requestBodyLimitBytes(config)` in `shared/lib/upload-limits.ts`: the larger
  of the two caps plus the multipart slack; `index.ts` uses it.
- `.env.example` notes on both variables (regenerated env reference).

## Verification

- RED: `upload-limits.test.ts` expects the backup cap to win when it is the
  larger value.
- `bun run check` EXIT 0.
