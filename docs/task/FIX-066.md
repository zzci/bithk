# FIX-066 - CLI script commands unreachable in release; unknown command boots the server

- Status: Completed
- Plan: [PLAN-106](../plan/PLAN-106.md)
- Created: 2026-07-06

## Problem (user-reported, production)

Running the new migration command in a release printed
`error: Failed to start server. Is port 3000 in use?`.

Two causes:

1. **The `script:*` (and `backup:blob-rescan`) commands were never exposed in
   the packaged artifact.** `scripts/package.ts` only wrote `start`,
   `healthcheck`, `migrate`, `backup:export`, `backup:import` into the staged
   `package.json` — so there was no `lode`-runnable entry for the migration
   scripts in a release.
2. **An unrecognised subcommand silently fell through to booting the server**
   (`cli/index.ts` returned `null` on any unmatched positional, and
   `index.ts` then ran `Bun.serve`). With the real server already on port
   3000, that surfaced as the misleading "Failed to start server" instead of
   "unknown command".

## Fix

- `scripts/package.ts`: add `backup:blob-rescan`, `script:rekey-legacy-blobs`,
  `script:migrate-all-to-s3` to the staged `package.json` scripts.
- `cli/index.ts`: when a positional is present but matches no command, print
  `unknown command: …` and return exit 2 (never boot the server). A bare
  invocation with no positional still returns null → boots the server.

## Verification

- `cli/index.test.ts`: no positional → null; `--help`/`--version` → 0; unknown
  command → 2; a known command dispatches.
- `bun run check` green.
