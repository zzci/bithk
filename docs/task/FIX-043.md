# FIX-043 Cover/avatar image URLs omit BASE_PATH (404 under base-path deploys)

- Status: Completed
- Plan: -
- Owner: local-session
- Updated: 2026-06-16

## Goal

Project and ship cover images (and contact avatars) do not display when the app
is deployed under a non-root base path (the documented production config
`BASE_PATH=/app`). Make the server-built `<img>` URLs respect `BASE_PATH`.

## Root cause

The web fetch client prepends the base path (`apps/web/src/shared/lib/http.ts`:
`BASE_URL = ${import.meta.env.BASE_URL}/api`, and Vite's base is `BASE_PATH`).
But the backend builds the image URLs rendered directly in `<img src>` as a bare
`/api/files/:id/content?ref=...&inline=true` with no base path:
`ship.service.ts` `buildCoverUrl`, `project.service.ts` `buildCoverUrl` (+ the
default cover), `contact.service.ts` `buildAvatarUrl`. Under `BASE_PATH=/app` the
API is mounted at `/app/api`, so `fetch()` works but a plain
`<img src="/api/files/...">` resolves to `/api/...` (no `/app`) → 404 → the cover
never displays. Attachments are unaffected (they go through the `http` client,
which adds the base). Not caught by tests because dev + unit tests run with
`BASE_PATH=""`, where the bare `/api` path is already correct.

## Scope

- `apps/api/src/modules/file`: add a `BASE_PATH`-aware URL helper
  `fileInlineContentUrl(fileId, referenceId)`, with the base set once at
  `initFileModule(config)` — mirroring how `storage/local.ts` caches `localRoot`
  at `setup(config)`. Export it from the file module barrel.
- `apps/api/src/modules/{ship,project,contact}/*.service.ts`: replace the local
  bare-`/api` URL builders with the shared helper.
- Tests: assert the URL carries the configured base path.

Out of scope: the FEAT-032 normal-user module-gate 404s (separate issue); the
web side (it already handles BASE_PATH for fetch).

## Acceptance

- With `BASE_PATH=/app`, cover/avatar URLs start with `/app/api/files/...`; with
  `BASE_PATH=""` they stay `/api/files/...` (no behaviour change in dev).
- `bun run check` passes.
