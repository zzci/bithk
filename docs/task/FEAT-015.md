# FEAT-015 Introduce global typed tags

- Status: Done
- Plan: [PLAN-023](../plan/PLAN-023.md)
- Owner: BKD L2 g7amf4od
- Updated: 2026-05-28

## Goal

Introduce one centrally maintained tag vocabulary with a type/source
discriminator so project, contact, document, and future domain tags do not
depend on module-local tag storage.

## Scope

- Backend tag schema, Drizzle model, generated migration, backup ordering, and
  API tag routes.
- Project, contact, and document tag persistence/query code.
- Frontend API types/hooks that consume tag endpoints.
- Focused backend/frontend tests, fixtures, API route docs, module docs, and
  changelog entries required by the breaking model change.

Out of scope: unrelated database normalization, auth/permission redesign,
unrelated module rewrites, dependency upgrades, and broad UI redesign.

## Acceptance

- Current tag implementations and consumers are investigated before editing.
- The `tags` table has a type/source discriminator and type-scoped uniqueness.
- Project and contact joins use the typed global vocabulary.
- Document tags no longer live only as a JSON text field; they use global typed
  tags through a document join table.
- Drizzle migration is generated by the project toolchain only.
- Affected tests, fixtures, docs, and frontend API types/hooks are updated.
- Focused checks and `bun run check` pass after integration.
