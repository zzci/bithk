# FIX-053 - Backup export: opt-in blobs, per-row driver-aware (DB-record driven; local bytes, S3 skipped)

- Status: Completed
- Plan: [PLAN-102](../plan/PLAN-102.md)
- Owner: local-session
- Created: 2026-07-01

## Summary

User report: uploaded files are missing from backup exports even when blob
inclusion is selected. Investigation confirmed three defects in the v2 archive
writer (`modules/backup/archive.service.ts`):

1. Blob bytes are read ONLY from the single ACTIVE storage driver. Every
   `files` row whose `storage_driver` differs (e.g. local rows after switching
   to S3 via FEAT-044, quarantined rows, and soon `db` rows from FEAT-047) is
   silently skipped — the export completes "successfully" with the omission
   recorded only as a manifest warning.
2. One missing local blob (`local.getStream` throws) fails the ENTIRE export
   job instead of skipping that blob with a warning.
3. Manifest warnings are never surfaced: the export job poll response and the
   admin UI show no warning at all, so silent omissions are invisible.

Agreed design (user-specified):

- Export UI offers a single **"export blobs" checkbox, unchecked by default**
  (default = data-only export).
- Blob export is **driver-mix aware and independent of the active/upload
  driver selection**: which bytes to export is decided **per `files` row from
  its `storage_driver` DB record**:
  - `local` rows → bytes exported into the files artifact.
  - `s3` rows → NOT exported; UI states S3 must be backed up by the operator
    directly (out of scope).
  - `db` rows (FEAT-047) → content travels in the data archive via the
    `file_blob` table NDJSON; no blob entry.
  - quarantined/unknown drivers → skipped with a warning.
- A missing local blob skips that blob with a warning instead of failing the
  whole export.

## Acceptance Criteria

- UI: blobs mode select replaced by a checkbox (default unchecked → no files
  part). A visible hint states S3 files are not exported and must be backed up
  separately.
- Blob selection is driven purely by `files` rows' `storage_driver` (mixed
  local/s3/db sets export correctly regardless of which driver is currently
  active for uploads).
- A `files` row on `local` whose disk file is missing produces a warning and
  is skipped; the export still completes.
- `manifest.expectedBlobs` inventories every `files` row (any driver); s3 rows
  produce a summary warning surfaced in the poll response and UI.
- Import path unchanged and round-trips: local blobs restore; s3 rows
  reconcile against the bucket when reachable, quarantine otherwise.
- `bun run check` EXIT 0; focused tests cover mixed-driver export, missing
  local blob tolerance, warning surfacing, and default-unchecked (data-only)
  export.
