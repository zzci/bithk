# FIX-060 - Backup merge import: unique-key skip + auto id-remap; never abort on COMMIT FK

- Status: In Progress
- Plan: -
- Campaign: single BKD issue, worktree mode
- Created: 2026-07-05

## Bug (reproduced)

Merge-importing a backup into a DB that already holds the same logical entities under different
ids (e.g. fresh v0.2.0 deploy + first OIDC login, then import) aborts the WHOLE import with a raw
COMMIT-time `FOREIGN KEY constraint failed`. Repro: seed two DBs independently, export A, merge-
import into B.

Root cause (`apps/api/src/modules/backup/import-mapping.ts`): the rule-12 FK pre-check admits
children whose parent is in the upfront `incoming` to-be-inserted set (L525-542, L609), but the
parent later skips/fails on a unique-key collision (same email/oauthSub/name, different id) and
never lands; `defer_foreign_keys` postpones the dangling-FK detection to COMMIT, which aborts and
rolls back everything. The rule-14 id-map exists but nothing populates or auto-consumes it.

## Fix (user-approved design, 2026-07-05)

1. **Rule-11 upgrade — unique-key skip + auto remap (engine-level).** Duplicate probe: PK first;
   on miss, probe each UNIQUE index of the live table. On a unique-index hit whose live PK
   differs from the incoming PK: skip the row, record `idMap(table, incomingId -> liveId)`,
   count as `remapped` (existing rule-14 vocabulary). Users (oauth_sub, email), cron jobs
   (name), and every other uniquely-keyed table get this uniformly.
2. **Engine consumes the id-map.** In `processMappedRow`, before the duplicate probe and FK
   pre-check, rewrite every FK-referencing column value through the id-map (registry
   `references` metadata gives the target table). Transform-recorded mappings (rule 14) flow
   through the same substitution.
3. **COMMIT safety net.** Track rows admitted solely via the `incoming` promise; after the main
   loop (before COMMIT), fixpoint-verify those FK edges with live probes; delete rows whose
   parent never landed and count them `failed(missing-parent)` in the report. A merge import
   must never abort at COMMIT with a raw FK error — worst case is a per-row failure in the
   report.
4. Dry-run mode (`runImportDryRun`) reports the same outcomes (remapped/skip/fail) so the UI
   preview matches apply.

## Acceptance Criteria

- Repro passes: export seeded-A, merge-import into independently-seeded-B → import completes;
  users/cron-jobs (and other unique-keyed collisions) counted `remapped`/`skippedDuplicate`;
  children reference the LIVE ids (assert a child row's FK equals the live parent id).
- Same-DB re-import stays all-`skippedDuplicate` (no regression).
- A hand-broken archive with a truly missing parent yields `failed(missing-parent)` rows in the
  report, not a COMMIT abort.
- Replace mode and export untouched; `bun run check` EXIT 0.
