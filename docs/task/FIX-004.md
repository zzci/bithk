# FIX-004 Preserve login across new tabs

- **status**: completed
- **priority**: P1
- **owner**: main
- **createdAt**: 2026-05-25

## Description

Opening the app in a new tab can present the login form even when the browser
already has a valid single-user session cookie. The backend single-user login
flow writes an HttpOnly `session_id` cookie and `/account/me` reads it through
the normal auth middleware, so the session should be shared across tabs on the
same origin.

The frontend currently has two gaps:

1. The `/` route always navigates to `/login`.
2. The `/login` route renders the login mode/form without checking whether
   `/account/me` already succeeds.

This makes a logged-in session look absent when a user opens the root URL in a
fresh tab.

## ActiveForm

- Change the root route to land on `/overview`, letting the existing `_app`
  auth guard decide whether to keep the user or redirect to `/login`.
- Change the login route to check the current session before rendering the
  login form and redirect authenticated users to the requested safe redirect
  target.
- Add focused frontend coverage for authenticated root/login navigation.
