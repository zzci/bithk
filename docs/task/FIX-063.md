# FIX-063 - Sheet unopenable after save: multipart mimetype loss + duplicate-content autosave failure

- Status: In Progress
- Plan: -
- Campaign: single BKD issue, worktree mode
- Created: 2026-07-06

## Bugs (both reproduced)

### Bug 1 (user-reported, production): saved sheet loses its mimetype → cannot be opened

Bun 1.3.14's server-side `req.formData()` DROPS the multipart part's `Content-Type` — verified
with curl sending `type=application/x-univer-sheet` (and `application/pdf`, `text/plain`) against
a minimal `Bun.serve`: the parsed `File.type` is always `""`. Consequences:

- Every multipart upload path stores `files.mimetype = ""` (`file.service.ts:302` uses
  `file.type` directly): drive version uploads (sheet saves!), drive multipart uploads
  (non-presign), issue/procurement/document/hr attachments, comment attachments, covers/avatars.
- The Univer sheet editor's save (`POST/PUT /drive/entries/:id/versions*`) therefore produces a
  version blob with empty mimetype; the entry's display file loses `application/x-univer-sheet`
  and sheet-detection surfaces that key on the mime (`file-preview-types.ts:110` has NO suffix
  fallback, unlike `isUniverSheetEntry`) stop routing it to the editor → "保存后无法打开".
- Presigned uploads are unaffected (mimetype travels in the JSON presign body,
  `upload-queue.ts:119`) — which is why older/S3 files still show correct types.

### Bug 2: autosave permanently fails after undo-to-saved-state (DUPLICATE_REFERENCE)

`overwriteEntryVersion`/`uploadEntryVersion` → `uploadAndReference` dedup: when the saved
content's sha256 equals ANY existing version blob of the SAME entry (user edits, then undoes
back to a previously saved state), the dedupe path tries to insert a second
`file_references (fileId, drive_entry, entryId)` row → unique violation → 400
`DUPLICATE_REFERENCE` (`file.service.ts:260`). The editor marks saveFailed and retries forever;
edits survive only in the localStorage draft. Reproduced service-level: create sheet(rev0) →
upload version(rev1) → overwrite(rev2) OK → overwrite(rev0 again) → throws.

## Fix design

### A. Server-side authoritative mime resolution (single choke point)

In `uploadAndReference` (file module): when `file.type` is empty, resolve the mimetype as
`declaredMime` input (new optional field) → content sniff (extend the existing mime-sniff module
with a best-effort `sniffMime(bytes)` for its known magic signatures) → extension map (small,
shared: .sheet/.pdf/.png/.jpg/.txt/.md/.csv/.json/... ) → `application/octet-stream`. Store the
resolved value in `files.mimetype` and pass it as the driver `contentType`.

### B. Versions inherit the entry's mimetype

`uploadEntryVersion` / `overwriteEntryVersion` pass `declaredMime` = the current version file's
mimetype (a version of a sheet is a sheet) so sheet saves stay
`application/x-univer-sheet` regardless of transport loss.

### C. Same-content save must succeed (fix Bug 2)

Teach the version paths to handle the same-owner duplicate: if the uploaded content dedups to a
file already referenced by this entry, reuse rather than fail —
EITHER return the existing reference without a new row and skip the
`releaseReference(previousRefId)` when it would release the reference now in use, OR pre-check
by sha256 against the entry's version blobs and short-circuit (repoint the version row to the
existing reference; never double-release). Preserve the invariant that every version row keeps a
resolvable `fileReferenceId` and ref_count stays consistent (test both directions).
Generic attachment flows keep the DUPLICATE_REFERENCE guard (double-attach is a real error
there) — scope the tolerance to the drive version paths via an explicit option.

### D. Repair existing rows + fallback hardening

- Idempotent repair pass for `files.mimetype = ''` rows: infer from sibling versions of the same
  entry, else extension map on the reference filename; run automatically at boot (cheap WHERE
  clause) — the user's existing broken sheets must open after upgrade with no manual steps.
- `file-preview-types.ts` sheet branch gains the same `.sheet` suffix fallback as
  `isUniverSheetEntry` (belt and braces for any rows repaired late).

## Acceptance Criteria

- Route-level test: multipart version upload whose File.type is empty (simulate Bun behavior —
  it IS the behavior) ends with `files.mimetype = application/x-univer-sheet`; sheet reopens
  (content fetch + JSON parse) and remains sheet-detected.
- Attachment multipart upload of a .pdf with empty File.type stores `application/pdf` (extension
  map) — no more empty mimetypes anywhere.
- Undo-to-saved-state sequence (create rev0 → save rev1 → overwrite rev2 → overwrite rev0)
  succeeds; versions list stays consistent; `PRAGMA foreign_key_check` clean; no double-release
  (ref_count assertions).
- Boot repair: a DB seeded with `mimetype=''` sheet rows opens correctly after startup.
- `bun run check` EXIT 0; e2e drive module green locally (`bun tests/e2e/run.ts`).
