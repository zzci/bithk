# FIX-044 e2e: grant module access to the non-admin actor (FEAT-032 gate)

- Status: Completed
- Plan: -
- Owner: local-session
- Updated: 2026-06-16

## Goal

13 e2e tests in document / drive / ship fail with route 404s after FEAT-032
made module visibility group-based. Make them pass without changing the
(intended) "no grants → no modules" Guest floor.

## Root cause

FEAT-032 (PLAN-081) gates the protected module prefixes by group membership:
a non-admin user in no module-granting group sees nothing — the deliberate
Guest floor (`module-gate.ts` `resolveUserModules`). The e2e DB is unseeded
(no "All Staff" group) and its non-admin actor `user@example.com` is created
lazily on OIDC login, so it belongs to no group and 404s on
`/documents`, `/drive`, `/ships`, etc. `admin@example.com` bypasses the gate,
so admin-driven suites still pass. This is stale-test setup, not a product bug
(the Guest floor is intended) — option (a) per the investigation.

## Scope

- `tests/e2e/lib/grant.ts`: `grantAllModules(email)` — as admin, create a group
  with every module key and add the user (idempotent via a unique group name
  per call; the grant persists in the shared run DB).
- `tests/e2e/modules/{document,drive,ship}/*.test.ts` (the failing suites): a
  `beforeAll` granting `user@example.com` module access.

Out of scope: any product change to the Guest floor / new-user defaults.

## Acceptance

- `bun run test:e2e` document/drive/ship suites pass; no resource-level negative
  assertion regresses (module grant ≠ resource permission).
- No product / non-test source changes.
