# FIX-039 Runtime branding from server settings

- Status: Completed
- Plan: [PLAN-072](../plan/PLAN-072.md)
- Owner: local-session
- Updated: 2026-06-09

## Goal

The packaged web app currently reads the display title from Vite build-time
environment variables. Make user-visible branding read from server runtime
settings so an installed release can change its display name without rebuilding
the frontend.

## Scope

- Add a non-sensitive system endpoint for public runtime branding.
- Resolve the display name from the settings table with an environment
  fallback.
- Update frontend title and visible brand labels to use the runtime value.
- Keep storage namespace behavior stable.

Out of scope: runtime logo uploads, CSS theme branding, changing localStorage
namespace semantics, or server-side HTML template rendering before JavaScript
loads.

## Acceptance

- The API exposes display branding without requiring authentication and without
  leaking generic settings.
- If the setting is present, the frontend login page, app shell labels, and
  `document.title` use it after startup.
- If the setting is missing or the request fails, the frontend falls back to the
  current build-time display name.
- `APP_NAME` continues to namespace web storage and backup filenames as before.
- Focused API and frontend tests cover the runtime branding behavior.
- `bun run check` passes.

## Notes

- 2026-06-09 - Investigation found `APP_DISPLAY_NAME` is baked into the web
  bundle through Vite, so packaged frontend code will not reread deployment
  environment variables at runtime.
- 2026-06-09 - Implemented public runtime branding via `/api/system/branding`,
  settings seeding for `app.display_name`, frontend runtime consumers, and
  focused tests. Verified with `bun run check` and `bun run package`.
