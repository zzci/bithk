# PLAN-078 - HR approvals and payroll sub-modules

- Status: Completed
- Task: [FEAT-026](../task/FEAT-026.md), [FEAT-027](../task/FEAT-027.md)
- Campaign: local
- Created: 2026-06-10

## Context

FEAT-025 renamed the finance module to HR and pre-mounted Approvals and
Payroll as placeholder tabs under the `/hr` layout. The user now wants both
implemented as working sub-modules. Constraints confirmed by the user:

- Payroll must support multiple currencies.
- Both sub-modules stay admin-only (the existing `/hr` layout guard and
  `adminRequired` route gate; no employee self-service in this pass).

Reusable precedents: the colleagues sub-module (`hr.service.ts`,
`hr.routes.ts`, `hr.routes.test.ts`, `-colleagues-page.tsx`) for module
mechanics; procurement for money conventions (`amount` integer in minor
currency units + `currency` text, displayed raw with the code suffix);
const-array status enums.

## Proposal

1. Schema (`apps/api/src/modules/hr/schema.ts`):
   - `hr_approvals`: `id`, `colleague_id` (FK → `hr_colleagues.id` ON DELETE
     RESTRICT), `type` (`leave | overtime | business_trip | other`), `title`,
     `reason`, `status` (`pending | approved | rejected`, default pending),
     `decided_by` (FK → `users.id` ON DELETE SET NULL), `decision_note`,
     `decided_at`, timestamps; indexes on `status` and `colleague_id`.
   - `hr_payroll_records`: `id`, `colleague_id` (FK RESTRICT), `period`
     (`YYYY-MM`), `base_salary` / `bonus` / `deduction` (integers, minor
     currency units), `currency` (3-letter uppercase code — multi-currency,
     validated by format, not an enum), `net_amount` (server-computed
     base + bonus − deduction, must be ≥ 0), `status` (`pending | paid`,
     default pending), `paid_at`, `notes`, timestamps; unique
     `(colleague_id, period)`, indexes on `status` and `period`.
   - Migration generated by drizzle-kit (pure CREATE, no rename prompt).
2. Services: `hr.approvals.service.ts` and `hr.payroll.service.ts`.
   Invariants:
   - Approvals: applicant must be an existing **active** colleague; decided
     records (approved/rejected) are immutable — update, re-decide, and
     delete all return 409; deciding stamps `decidedBy/decidedAt`.
   - Payroll: one record per colleague per period (409 on duplicate); paid
     records are immutable (409 on update/delete); marking paid stamps
     `paidAt` and cannot be reverted; negative net → 400.
3. Routes (extend `hr.routes.ts`, all `adminRequired`):
   - `GET/POST /hr/approvals`, `PATCH /hr/approvals/:id`,
     `POST /hr/approvals/:id/decision`, `DELETE /hr/approvals/:id`.
   - `GET/POST /hr/payroll`, `PATCH /hr/payroll/:id` (also marks paid via
     `status: "paid"`), `DELETE /hr/payroll/:id`.
   - List rows carry joined applicant display data (name, username,
     isVirtual) and the decider name for approvals.
4. Backup: extend the `hr` contribution tables to
   `[hrColleagues, hrApprovals, hrPayrollRecords]` (deps `users` unchanged;
   in-module order restores colleagues first).
5. Frontend:
   - Data layers `shared/lib/api/hr-approvals.ts` / `hr-payroll.ts` (query
     keys `["hr", "approvals"]` / `["hr", "payroll"]`) + tests.
   - Replace the placeholder routes with real pages following the colleagues
     page pattern (`index.tsx` + `index.lazy.tsx` + `-approvals-page.tsx` /
     `-payroll-page.tsx` + tests): list with filters, create/edit dialog
     with colleague picker, approve/reject dialog (approvals), mark-paid
     and currency select (payroll, curated code list in the UI).
   - Remove `-hr-placeholder.tsx` and the placeholder i18n keys; extend the
     `hr` namespace (en/zh) with approvals/payroll copy.
6. Docs: `docs/modules/hr.md`, database/API references, regenerate
   `api-routes.md`, changelog. Run `bun run check`.

## Risks

- Decide/mark-paid are one-way transitions enforced only in the service
  layer; covered by focused 409 tests.
- `decided_by` uses SET NULL so deleting an admin user does not orphan-block
  approval history (display falls back to a dash).
- Amounts are raw integers in minor units shown with the currency code —
  same convention as procurement; no per-currency decimal formatting in this
  pass.

## Scope

Two new tables + one generated migration, two services, route/test
extensions, two web pages + data layers + i18n, backup contribution update,
docs. Out of scope: employee self-service submission, approval chains /
multi-step workflows, payroll calculation rules, currency conversion.

## Alternatives

- Currency as a fixed enum: rejected — multi-currency was an explicit
  requirement; format validation (`^[A-Z]{3}$`) keeps new currencies a
  UI-list tweak instead of a schema change.
- Separate route modules per sub-module: rejected — one `hrRoutes()` mount
  keeps wiring identical to today; the routes file stays well under the
  size limit.
